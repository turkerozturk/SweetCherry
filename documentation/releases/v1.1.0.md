# SweetCherry 1.1.0

SweetCherry is an open-source web companion for CherryTree CTB note databases. This release adds easier configuration and database connections, with fixes validated on SQLite, MariaDB and PostgreSQL.

## Download and install

Windows 10/11 **64-bit** packages include **Java 17**; a separate Java installation is not required.

| Asset | Purpose |
| --- | --- |
| `SweetCherry-1.1.0-windows-x64-setup.exe` | Installation wizard and shortcuts. Choose a writable folder. |
| `SweetCherry-1.1.0-windows-x64.zip` | Portable application. Extract the complete folder before starting `SweetCherry.exe`. |
| `SweetCherry-1.1.0-notices.zip` | Third-party license and attribution files, also included in both application packages. |
| `SHA256SUMS.txt` | Checksums for the installer, portable ZIP and notices ZIP. |
| `windows-bundle.json` | Application version, exact build commit and bundled-runtime information. |

GitHub's Source code ZIP/tar archives contain source, not a ready-to-run application. Linux/Raspberry Pi users can build from source with JDK 17 or newer. No Windows 32-bit package is included; macOS scripts have not been verified on a physical Mac.

## New in 1.1.0

- Create or edit tenant connections with a wizard; desktop users can pick an existing local/network-share CTB file on the machine running SweetCherry.
- Switch between compatible SQLite, MariaDB/MySQL and PostgreSQL databases without changing a global Hibernate dialect setting.
- Edit selected application settings from the administrator web interface and restart with confirmation. A desktop YAML editor also manages local configuration overrides.
- Find icons by name, see selected icons outside the list, combine no-icon and explicit-icon filters, and use illustrated alphabetical selectors. Title colors have translated names with hex tooltips.

## Reliability and compatibility fixes

- MariaDB metadata detection, identifier quoting and new sibling/child creation queries.
- PostgreSQL rich-text object removal writes numeric object flags, not boolean values.
- Health checks skip intentionally closed/unstarted tenant pools while still reporting running-pool failures.
- Short, safe connection-failure explanations; no-database pages redirect to source selection before querying; invalid parent IDs are handled without SQL errors.
- Existing collection-CTB export uses its transaction connection; safe punctuation in exported filenames is accepted.
- Old SQLite CTB schema checks and explicitly permitted upgrade of missing `children.master_id`.
- Clear active/writable tenant status, missing System-menu icons, and routine search/table diagnostics controlled by `myapp.debug`.

## Upgrading from 1.0.0

Stop SweetCherry before replacing files. Preserve your CTB databases, tenant configs, external YAML, `login-credentials.properties` and exports. Extract the new package into a separate folder and carry over your own configuration/data deliberately. Do not replace your notes or passwords with demo files. Use the complete new runtime rather than merging Java folders. Existing external YAML overrides continue to take precedence over new defaults.

**SweetCherry does not create automatic backups.** Keep a separate backup before editing important notes or allowing a legacy schema upgrade. A compatible server database must already contain the CherryTree schema/content; selecting it does not perform a CTB migration. SweetCherrySync is a separate synchronization tool. Avoid editing a synchronization target while another application writes to it; later synchronization may overwrite changes.

## Validation and known limitations

The maintainer reported **393 passing tests** and manual verification on SQLite, MariaDB and PostgreSQL. Windows installer/launcher checks run separately when the final tag is packaged.

Content filtering still searches raw `node.txt`. Browser Back after a POST search may require form resubmission. Node IDs embedded in exported text links are not rewritten. Codebox editing and further rich-text refinements remain follow-up work. An isolated MariaDB 1020 record-change conflict will be investigated if it recurs; conflict protections were not removed.
