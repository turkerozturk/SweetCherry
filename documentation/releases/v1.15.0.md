# SweetCherry 1.15.0

Prepared on **26 November 2026**. This release adds in-place tree editing, more practical rich-text clipboard and object handling, broader raster image imports and updated Java security checks while keeping Java **17+** compatibility and the existing CherryTree CTB format.

## Downloads

| Asset | Purpose |

| `sweetcherry_1.15.0_all_os_portable_with_java_and_setup.exe` | Windows x64 setup/extraction wizard, launcher and bundled security-patched Java 17. |

Keep the complete application folder together. The installer and its bundled Java are Windows-only despite the `all_os` filename; macOS and 32-bit/i386 remain untested.

## Changes since 1.14.0

- Added in-place plain-text, code, Markdown, HTML and rich-text editors inside the `/tree` content pane.
- Preserved reading preferences and scroll position when returning from editing, with independent split-pane editing and unsaved-change guards.
- Grouped crowded application, view and reader-preference menus into click-to-open sections suitable for keyboard and narrow-screen use.
- Added portable clipboard snapshots of loaded images, tables and codeboxes that paste as fresh objects, including into another rich-text editor.
- Added Delete/Backspace, Cut and paste-over-selection for object-containing selections when Allow object deletion is enabled, sharing text undo/redo history.
- Added confirmed retrieval of public images within pasted HTML while retaining the order of text, images and tables.
- Added local WebP, GIF, BMP, TIFF and WBMP decoding alongside PNG and JPG/JPEG, with new CTB images normalized to static PNG.
- Removed the former 8-image web-import and 10-new-object image caps while retaining byte, pixel and time budgets.
- Updated CI and Windows bundling to require security-patched Java, including the November 2026 CVE-2026-114938 fix.
- Replaced mismatched Maven wrapper scripts with Apache Wrapper 3.3.4 `only-script` launchers and checksum-verified Maven downloads.

## Java security and upgrades

Windows packaging downloads the latest available Temurin 17 JRE and refuses metadata or an extracted runtime below **17.0.21.1**. It verifies the downloaded archive's SHA-256 and records the selected release in `build-info.json`. The fixed Temurin release for CVE-2026-114938 is **17.0.21.1+2**; use the workflow summary and extracted `runtime/bin/java.exe -version` output to check the actual bundled release before publishing.

This is the November 2026 security baseline, not a promise against future vulnerabilities. Java-free ZIP users must maintain their own patched Java; Java 21/25 installations also need the applicable vendor patch. See [security guidance](https://github.com/turkerozturk/SweetCherry/blob/v1.15.0/SECURITY.md).

Stop SweetCherry before upgrading, back up CTBs and preserve your own configuration, credentials, saved searches and data. Extract to a new folder and transfer private data deliberately. Replace a bundled runtime as a complete folder; do not merge it with an old runtime. Application updates do not update an adjacent old runtime or system Java automatically.

## Image import and editing notes

- Animated GIF/WebP and multipage TIFF use their first frame/page; animation is not retained. SVG and AVIF are outside this raster import path.
- There is no fixed image-count cap, but the normal 9 MB tenant per-file limit, total upload/download budgets, decoded-pixel limits and timeouts still apply; the source and normalized PNG must both fit.
- Web images can also be skipped because they require cookies/login, reject direct requests, use unsupported URLs/formats, or appear only after JavaScript runs. SweetCherry does not use the browser's login cookies or run webpage scripts.
- Existing saved file attachments and anchors still copy as explicit text placeholders; Cut preserves the selection if any object cannot be fully snapshotted. Newly staged attachments and supported loaded images/tables/codeboxes can be copied as objects.
- Keep Allow object deletion enabled when saving staged object removals; Manage objects remains available. CTB changes happen only on Save.
