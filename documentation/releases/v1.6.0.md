# SweetCherry 1.6.0

SweetCherry is an open-source web companion for CherryTree CTB note databases. This release adds consistent CTB backups, optional scheduled backups and retention, reviewed backup deletion, recent home activity and more comfortable editors.

## Download and install

Windows 10/11 **64-bit** packages include **Java 17**; a separate Java installation is not required.

| Asset | Purpose |
| --- | --- |
| `SweetCherry-1.6.0-windows-x64-setup.exe` | Installation wizard, desktop launcher and shortcuts. Choose a writable folder. |
| `SweetCherry-1.6.0-windows-x64.zip` | Portable application. Extract the complete folder before running `SweetCherry.exe`. |
| `SweetCherry-1.6.0-notices.zip` | Third-party licenses and attributions, also included in both application packages. |
| `SHA256SUMS.txt` | Checksums for the installer, portable ZIP and notices ZIP. |

## New in 1.6.0

- **Consistent CTB backups:** as ADMIN, create a full snapshot of a file-based SQLite database using the SQLite Online Backup API. Integrity checks, record counts and streaming SHA-256 verification precede publication. Read-only connections are supported; changing the selected connection does not change a running job's source.
- **Safe recovery into a separate copy:** download a verified CTB or open an independent working copy through the existing wizard, initially read-only. The original database and stored snapshot are not overwritten. This is whole-database backup, not per-node version history or in-place restore.
- **Optional scheduling and retention:** explicitly enable automatic backups and list the connections to include. Aliases pointing to the same physical CTB are grouped; jobs run sequentially and failures use retry backoff. Retention runs only after a successful automatic backup and affects automatic snapshots of that same source, preserving manual/legacy snapshots and working copies.
- **Review old backups before deletion:** select one or multiple catalog entries, review exact filenames and sizes, then confirm. Session-bound, single-use confirmation expires after ten minutes. Rechecks protect changed snapshots, registered database files, running outputs and SQLite journal sidecars; results distinguish deleted and skipped files.
- **Home activity:** the virtual root shows separate Created and Modified lists with icons, title styles, dates and clickable full breadcrumbs. Today's entries are supplemented with older entries to configurable minimums. Existing timeline/bookmark links are buttons. Bundled YAML now opens the most recently modified node after database selection; choose the virtual root with `open-latest-modified: false`.
- **Editor comfort:** rich-text and plain-text desktop writing areas use the available viewport rather than extending below it. Remove nested writing-area scrolling and unnecessary labels/whitespace; keep the rich-text caret visible, compact recovery controls, and align Markdown source and preview. Mobile rich-text tools retain their drawer.
- **Searchable code languages:** Node Properties has an alphabetical language picker with icons, filtering and a Markdown shortcut. Existing syntax/read-only locks remain in effect.
- **Resource fixes:** PDF option translations use Spring's message source; a missing language-specific code icon falls back to the generic code icon.

## Upgrade from 1.5.0

Stop SweetCherry and preserve your CTBs, external YAML files, tenant configurations, login-credentials.properties, exports and private saved filters. If already present, keep the complete backup folder, including its JSON catalog entries and working copies. Install/extract into a separate writable folder and deliberately copy your data/configuration across. Do not replace private data with bundled demos or merge old/new Java runtime folders. No CTB schema change is required by this release.

Existing external YAML is preserved and takes precedence. If it explicitly sets `myapp.home.open-latest-modified: false`, change it to `true` and restart to adopt the new bundled opening preference. The bundled activity-list minimum is five per list; zero hides that list. These are minimum counts, not caps on today's entries.

**Automatic backup remains off by default.** Enable `myapp.ctb-backup.automatic.enabled`, explicitly list tenant names, and restart. Defaults are a 1,440-minute interval, five-minute retry backoff and `keep-last: 0` (no automatic deletion). Existing backups become eligible for configured retention only after a new successful automatic snapshot of their source. See the backup guide before enabling retention.

## Validation and limits

The maintainer reported **648 passing Java tests** and successful manual editor/language-picker checks on feature commit `ce515d9`. The backup features and home activity were also manually checked during development. Build the final **v1.6.0 tag**, inspect its version/commit manifest and try its Windows package before publication. This note does not claim the release workflow has already run.

Backups cover file-based SQLite CTB databases, not MariaDB/MySQL/PostgreSQL or in-memory SQLite. They contain committed database content and embedded objects, not unsaved editor drafts, external linked files or application credentials/settings. Keep downloaded copies on another disk/device: a backup beside the original does not protect against disk loss. Checksums detect changes but are not digital signatures. Recovery/deletion may require additional disk space and checksum time, particularly on Raspberry Pi. External programs do not participate in SweetCherry's file-use coordination; do not edit a stored snapshot directly or write to one CTB simultaneously from multiple applications.

Browser-local recovery drafts remain separate from backups. Existing limitations of raw-content search, Markdown, clipboard formats and synchronization still apply. Two previously reproduced duplication JavaScript test failures remain separate test-maintenance items and are not part of the passing Java test count.
