# SweetCherry 1.8.1

Prepared on **13 November 2026**. This security and maintenance release is recommended for users of 1.8.0 and earlier. It retains **Java 17+** and the existing CherryTree CTB structure. Final tagged packages must pass the release checks before publication.

## Downloads and platforms

| Asset | Purpose |
| --- | --- |
| `sweetcherry_1.8.1_all_os_portable.zip` | Complete portable application and Windows/Linux/macOS scripts, **without Java**. Requires a matching system Java 17+ and native SQLite support. |
| `sweetcherry_1.8.1_all_os_portable_with_java_and_setup.exe` | Windows x64 setup/extraction wizard, application, desktop launcher and bundled Windows Java 17. **Windows x64 only**, despite the `all_os` name. |
| `sweetcherry-1.8.1-third_party_licences.zip` | Convenience copy of the third-party licences and notices also included in both application packages. |
| `sha256sums.txt` | SHA-256 checksums of the three files above. |

The ZIP is intended for Windows and Linux, including Raspberry Pi ARM with suitable Java/native dependencies. macOS scripts are included, but **macOS and 32-bit/i386 systems remain untested**. The bundled Windows runtime cannot be used on Linux or macOS. Node.js is needed for the JavaScript development tests, **not to run SweetCherry**.

## Security changes since 1.8.0

- **Framework and dependency maintenance** ([3871597](https://github.com/turkerozturk/SweetCherry/commit/3871597), [3f71f76](https://github.com/turkerozturk/SweetCherry/commit/3f71f76)): migrate to Spring Boot 4.1.2 and its compatible framework, security, ORM, JSON and web-server stack. The packaged stack includes Spring Framework 7.0.10, Spring Security 7.1.2, Hibernate 7.4.13.Final, Tomcat 11.0.27 and Jackson 3.1.7; remaining Jackson 2 dependencies are aligned on 2.21.7. Reviewed HTTP, logging and OGNL maintenance updates are retained. Springdoc and Thymeleaf extensions are updated for compatibility. Java 17 remains the minimum.
- **Settings and database connections** ([2e4047c](https://github.com/turkerozturk/SweetCherry/commit/2e4047c)): explicitly use safe YAML construction, reject custom tags and limit nesting. Validate supported JDBC drivers against their URL schemes before changing registrations, reject SQLite remote-resource connections and prevent local CTB paths from becoming JDBC options.
- **Web-content import**: preserve and verify checked, immutable DNS answers for the actual connection. Validate each redirect again, including same-host redirects. Retain scheme/port, response-size, time and request-budget limits. Private/local web destinations remain blocked; ADMIN-configured database connections follow a separate policy.
- **Export files and search** ([3f71f76](https://github.com/turkerozturk/SweetCherry/commit/3f71f76)): apply a shared export-folder boundary to file creation, listing, download and deletion, with filename and symlink checks. Generate search ordering from fixed choices while keeping filter values as bound SQL parameters.
- **Clipboard and cookies** ([3f71f76](https://github.com/turkerozturk/SweetCherry/commit/3f71f76)): sanitize pasted HTML with bundled offline DOMPurify before converting it into CTB content. Add HttpOnly and SameSite=Lax to the view preference cookie, with Secure when the request is HTTPS. Local plain-HTTP operation remains supported.
- **Reporting and regression checks**: add [SECURITY.md](../../SECURITY.md), private reporting guidance and JavaScript tests in both Windows/Linux CI and the Windows distribution workflow. A failed JavaScript test stops the workflow before packaging. The dependency notice inventory is refreshed against the actual packaged JAR; the Windows distribution workflow checks its JAR hashes before bundling.

Framework 7.0.10 contains the OSS fixes for the reported [XsltView advisory](https://spring.io/security/cve-2026-47884/) and [SSE-fragment advisory](https://spring.io/security/cve-2026-47890/). For the technical review, see [security alert review](../en/security-alert-review.md).

Before this preparation, the maintainer reported **zero open Dependabot alerts** and reviewed/dismissed the three remaining CodeQL alerts with individual reasons: custom web-import SSRF controls, intentional trusted-ADMIN database destinations, and intentional trusted-ADMIN server-side CTB selection. Dismissal is not an automatic code fix or a guarantee that related bypasses cannot exist. Alert counts are a dated observation, not a permanent security claim. No blanket CodeQL exclusions are introduced by this release preparation.

## Other maintenance changes

- **Node properties and status icons** ([996332e](https://github.com/turkerozturk/SweetCherry/commit/996332e)): edit CherryTree-compatible This Node / The Subnodes search-exclusion flags, stored as bits in `node.level`. Show read-only, bookmark and exclusion icons in content headers and compact tree badges. This adds flag editing/display; it does not introduce universal exclusion filtering across every SweetCherry search or list. These flags are not an access-control mechanism.
- **Session messages** ([358d489](https://github.com/turkerozturk/SweetCherry/commit/358d489)): all expired-session, changed-database, connection-check and home-link overlay messages use English/Turkish translations.
- **Jackson compatibility**: older manual-backup manifests without automatic-backup fields remain readable. Saved-filter parsing retains the existing error-handling contract. Existing stored JSON files are not rewritten merely by upgrading.

## Upgrade instructions

1. Stop SweetCherry and any other application writing to the same CTB.
2. Back up your CTBs, YAML settings, `allTenants`, `login-credentials.properties`, `saved-filters`, exports and complete backup directories. Include databases stored outside the application folder and use a backup method appropriate to any remote database server.
3. Extract/install 1.8.1 into a **new writable folder**. Keep the complete application folder together. Do not copy an older JAR, EXE or bundled Java runtime over the new files.
4. Transfer your own data and supported configuration deliberately. Preserve existing credentials; do not replace private data with bundled demos. Existing external configuration takes precedence over packaged defaults.
5. Start the new launcher or script, sign in, select a database and check normal reading/editing and backups using a disposable database copy first.

No new CTB schema migration is introduced by this release. The explicitly permitted legacy-schema upgrade retains its existing behavior. Supported connection drivers are SQLite, PostgreSQL, MariaDB and MySQL; unsupported JDBC drivers and SQLite `:resource:` configurations must be replaced. Review skipped connections in the application log. Trusted ADMIN accounts retain deliberate server-side file/database access; do not delegate that role to untrusted users.

GitHub's dependency alerts for `main` do not update already downloaded 1.8.0 packages. Install the newly built 1.8.1 package to receive these changes. Published release tags must not be moved or silently rebuilt with different application code.

## Building and validation

Build the `v1.8.1` tag with JDK 17+ and the Maven wrapper. Use the **entire generated `release/SweetCherry` folder**. To run the development JavaScript checks, install Node.js 24 and run `node --test src/test/js/*.test.cjs` from a shell that expands the file pattern, as Git Bash does in the workflows. No npm installation is required for these tests.

The maintainer reported **784 Java tests, zero failures/errors and two skipped tests** after applying the Boot migration and session-message translation. These are prior Windows results, not a claim that the final 1.8.1 binaries have already passed testing. Confirm Windows/Linux CI and the tagged distribution workflow before publication, including Java-free ZIP contents, bundled Java metadata, checksums and installer/launcher smoke checks.

Local preparation on 64-bit Linux with Corretto 17.0.21 passed `clean package`: **782 Java tests, zero failures/errors/skips**. Node.js 24.22.1 passed **147 JavaScript tests**. The packaged application version, Java 17 bytecode, included policy/guides and all **203 dependency-JAR hashes** were verified. Workflow YAML and test ordering were checked locally; GitHub Windows execution and the final setup EXE still require the tagged workflow checks above.

Before publishing, try login/logout, language changes, CTB opening/creation, rich-text paste and web import, Markdown/HTML editing, saved filters, backups and CTB/ZIP/MM export/import. Where used, check real MariaDB/MySQL/PostgreSQL connections and HTTPS/trusted-proxy operation. Preserve independent backups and avoid simultaneous writes from SweetCherry and CherryTree.
