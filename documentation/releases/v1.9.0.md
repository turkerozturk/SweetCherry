# SweetCherry 1.9.0

Prepared on **13 November 2026**. This feature release adds new ways to explore and connect existing CherryTree notes while retaining **Java 17+** and the existing CTB schema. Release preparation does not itself publish a tag or binaries.

## Downloads

| Asset | Purpose |
| --- | --- |
| `sweetcherry_1.9.0_all_os_portable.zip` | Complete portable application and Windows/Linux/macOS scripts, **without Java**. Requires matching system Java 17+ and supported native SQLite dependencies. |
| `sweetcherry_1.9.0_all_os_portable_with_java_and_setup.exe` | Application, desktop launcher and bundled Windows Java 17, with a setup/extraction wizard. **Windows x64 only**, despite the `all_os` filename. |
| `sweetcherry-1.9.0-third_party_licences.zip` | Convenience copy of the licences/notices already included in both application packages, now also including Cytoscape.js. |
| `sha256sums.txt` | SHA-256 checksums of those three assets. |

The Java-free ZIP is intended for Windows and Linux, including suitable Raspberry Pi ARM configurations. macOS scripts are included, but **macOS and 32-bit/i386 systems remain untested**. The bundled Windows runtime cannot run on Linux or macOS. Node.js is only needed for development tests, not application use.

## Changes since 1.8.1

- **Daily calendar** ([037b76b](https://github.com/turkerozturk/SweetCherry/commit/037b76b)): add `/calendar/day` and `/nodes/calendar/day`, chronological cards with creation time, node icon/title style, bounded text previews and attachment/image/table/codebox counts. Three columns fit wider desktops; mobile uses one column. Retain tag filters, date navigation and the existing date-editing dialog. Preview size and daily card limits are configurable.
- **Confirmed rich-text conversion** ([8ef3dc3](https://github.com/turkerozturk/SweetCherry/commit/8ef3dc3)): allow Rich Text to Plain Text or a supported code syntax, including Markdown/HTML, from Node Properties. A localized confirmation explains the loss. Preserve readable text, table cells, codebox text and link targets; remove images, attachments and anchors, leaving labels/filenames. Reject stale source revisions and save atomically. Improve the properties layout.
- **Dark theme and application settings** ([bdba476](https://github.com/turkerozturk/SweetCherry/commit/bdba476)): keep the existing light appearance by default and add `myapp.appearance.theme: dark`. Apply through external YAML or the administrator settings page after restart. Preserve authored rich-text colors on light content paper. Add validated initial language, home activity lists, tree width, calendar/day-preview, text-tree export and record-layout settings.
- **Focused connection map** ([e89159d](https://github.com/turkerozturk/SweetCherry/commit/e89159d)): use bundled offline Cytoscape.js for incoming/outgoing internal links, optional hierarchy, shared occurrences, an isolated content preview, accessible node list and Back/Forward focus history. Clicking a node makes it the focus. Use bounded derived indexes with rescan and partial-result warnings; no graph tables or stored coordinates are added.
- **Wiki-style rich-text links** ([a343625](https://github.com/turkerozturk/SweetCherry/commit/a343625)): turn `[[Exact name]]` or `[[Exact name|label]]` into ordinary CherryTree internal links on save. Unique exact names resolve automatically; duplicate names require breadcrumb/ID selection, including shared positions. Missing names remain complete expressions after explicit review; no nodes are auto-created. Existing links and codebox contents are excluded. Preserve formatting/object positions and revalidate chosen targets during save. Move Connection Map above Mind Map 1 with the same diagram icon.
- **Wiki preflight hardening** ([b56df67](https://github.com/turkerozturk/SweetCherry/commit/b56df67)): remove browser-side XML reparsing. Send serialized XML as opaque text to the hardened server reader, with regression coverage for encoded markup and split XML text runs. The maintainer reported the associated CodeQL alert resolved after pushing this fix; this is not a blanket security guarantee.

## Upgrade and configuration

1. Stop SweetCherry and other applications writing to the same CTB. Back up CTBs, configuration, `allTenants`, credentials, saved filters, exports and complete backup directories, including any external or remote data sources.
2. Install/extract into a **new writable folder**. Keep the whole application folder together. Transfer your own data/configuration deliberately; do not overwrite private data with demos or copy old program/runtime files over the new version.
3. Existing external YAML takes precedence over packaged defaults. Add desired new settings or use **System → Application settings**. Save and restart to activate changes; browser language/tree-width choices and environment/command-line overrides retain their existing precedence.
4. Test on a disposable CTB copy, including backups, reading/editing, the new views and whichever import/export or remote database features you use.

For example, merge these keys into your existing `myapp` mapping rather than creating a second mapping:

```yaml
myapp:
  appearance:
    theme: light # light or dark; restart after changing
  calendar:
    day-max-entries: 300
    day-preview-max-characters: 600
    day-preview-max-lines: 8
```

No new CTB schema migration is introduced. The existing explicitly permitted legacy-schema upgrade behavior is unchanged. Do not write to the same CTB simultaneously from SweetCherry and CherryTree.

## Important behavior and limits

- **Type conversion is lossy.** Save required attachments separately before converting and keep a CTB backup. The page cannot undo conversion or convert the result back to Rich Text. Shared occurrences of the source show the converted content. Unlock/save/reopen a read-only node before changing its type. Selecting Markdown/HTML changes text interpretation; it does not generate Markdown/HTML markup. Limits remain 2,000,000 source/object-text characters and 2,000 objects.
- **The theme changes application appearance.** Rich-text paper/visual editing, rendered code and sandboxed HTML previews retain light content surfaces for authored colors. Exported documents and the desktop launcher are unchanged.
- **The connection map is read-only and bounded.** It derives existing rich-text/object internal links; common tags and Markdown/HTML/plain-text source strings do not create edges. Shared tree positions remain distinct. Select 40/100/200 neighbours. The index is cached for up to 30 seconds; use Rescan links after edits. Scan limits can produce an explicitly partial map or reject oversized metadata sets. Full numeric limits are in the [setup guide](../en/setup-and-run.md#focused-connection-map).
- **Wiki names match exactly, including case and accents.** A name can refer to several tree positions. `\[[Name]]` stays literal, including the backslash, so later saves also leave it alone. Expressions do not cross line/object boundaries. Limits are 200 occurrences, 50 distinct names and 20,000 available tree positions; at most 200 candidates per name are shown. The feature is confined to the dedicated rich-text editor. Failed checks keep editing/recovery available.

## Build and validation

Use JDK 17+ and the Maven wrapper. Source users must run from the **entire generated `release/SweetCherry` folder**. JavaScript tests use Node.js 24 (`node --test src/test/js/*.test.cjs` in Git Bash or another shell expanding the pattern); no npm installation is required.

Before this preparation the maintainer reported **815 Java tests, zero failures/errors and two skipped tests**, successful manual feature checks and a resolved wiki-link CodeQL alert. Local feature/fix checks passed **813 Java tests and 159 JavaScript tests** on Linux, and verified the unchanged **203 dependency-JAR hashes**. These results do not certify the final Windows setup EXE. Check the release-preparation build, Windows/Linux CI and the tagged Windows distribution workflow, then smoke-test both final application packages before publication. The [release checklist](../tr/release-checklist.md) covers tagging, asset names, checksums and package checks.
