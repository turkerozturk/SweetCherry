## Upgrade and configuration

Stop SweetCherry and other CTB writers. Preserve separate backups of your databases, external configuration, tenant definitions, credentials, saved filters and exports. Extract/install into a new writable folder and transfer your data deliberately; do not overwrite private CTBs with demo files or mix old program/runtime files into the new application.

Existing external YAML takes precedence over bundled defaults. Merge these settings into the existing `myapp` mapping rather than creating a duplicate mapping. System settings changes require a restart.

```yaml
myapp:
  reminders:
    enabled: true
    alarms-enabled: true
    sound-enabled: true
  tree:
    show-tag-indicator: true
```

- The reminder master switch overrides panel and sound switches. Disabling reminders hides their links/forms and the floating alarm panel, and rejects reminder/alarm requests. Disabling only alarms keeps reminder forms/lists; disabling only sound keeps visual alerts.
- Browser mute/stop choices remain effective across pages. Sound is attempted automatically when allowed; browser autoplay restrictions may still require interaction or **Enable / test sound**. Automatic page startup does not play a test tone.
- Reminder records are ordinary protected metadata in a managed `REMINDERS` node. Disabling the feature does not delete them. Whole-CTB backups preserve them; subtree import/export does not automatically remap them. Do not edit or rearrange managed helper nodes manually.
- Existing v1 reminder records remain readable; the first mutation migrates them to v2. GET requests do not migrate. Older SweetCherry versions reject v2 records rather than overwriting them. Keep a pre-upgrade backup if rollback is needed.
- TODO completion changes tags; reminder completion is separate. Editing requires ADMIN, a writable source, CSRF and a current source token. Readers/read-only sources can view lists and document previews.

## Behavior and limits

Alarms work while a SweetCherry page is open, polling roughly every 20 seconds subject to browser throttling. Closed browsers, sleeping computers and suspended tabs cannot guarantee timely alerts. These are in-page alerts, without an operating-system scheduler or desktop notification. Closing an alert does not complete the reminder. Readers dismiss locally; writable ADMIN actions can persist dismissal/snooze. Browser receipts suppress repeated sounds across tabs; other browsers/devices may alert independently.

Annual reminders retain the month/day/local-time anchor. Choose February 28 or March 1 for February 29 in non-leap years. Completing an occurrence schedules the next future occurrence; missed years do not accumulate as separate entries.

Document previews are bounded reading views, without full Office page layout, charts, embedded images or tracked-change fidelity. Excel formula results are cached saved values and may be stale or absent. Formulas/macros are not executed and external document resources are not fetched. Download the original for the complete document.

Database statistics do not load note bodies or attachment BLOBs. The internal-link report scans content and may take time on large databases. Unreadable or oversized content produces explicit coverage warnings; the report never repairs links automatically.

## Validation and packaging

Before release preparation, the maintainer reported **993 Java tests, zero failures/errors and two skipped tests**, with successful manual checks. Preparation checks passed **211 JavaScript tests**, checked version metadata/local documentation links and patch applicability. Maven packaging could not run in the preparation environment because `repo.maven.apache.org` could not be resolved. The release preparation changes version metadata and documentation; those results refer to the preceding feature commit, not final release binaries. Run the preparation commit's CI and tagged distribution workflow, then smoke-test both final packages before publication.

Word preview added the matching Apache POI `poi-scratchpad` module during feature development; its notices and JAR inventory were updated in that feature commit. This preparation adds no further dependency. Verify the inventory against the actual packaged JAR using `python packaging/update-jar-notices.py --check`.
