# SweetCherry 1.10.0

Prepared on **15 November 2026**. This feature release adds object galleries, faster organization tools and optional recovery/history features while retaining **Java 17+** and the existing CTB schema. Preparation does not publish a Git tag, release or binary packages.

## Downloads

| Asset | Purpose |
| --- | --- |
| `sweetcherry_1.10.0_all_os_portable.zip` | Complete portable application and Windows/Linux/macOS scripts, **without Java**. Requires matching system Java 17+ and supported native SQLite dependencies. |
| `sweetcherry_1.10.0_all_os_portable_with_java_and_setup.exe` | Application, desktop launcher, bundled Windows Java 17 and setup/extraction wizard. **Windows x64 only**, despite the `all_os` filename. |

The Java-free ZIP is intended for Windows and Linux, including suitable Raspberry Pi ARM configurations. macOS scripts are included, but **macOS and 32-bit/i386 remain untested**. The bundled Windows runtime does not run on Linux or macOS. Node.js is needed only for development tests. Source users must use the **entire generated `release/SweetCherry` folder**, not the JAR alone.

## Changes since 1.9.0

- **Tags and quick tag editing** ([6cde2d1](https://github.com/turkerozturk/SweetCherry/commit/6cde2d1)): show parent names and created/modified dates, sort complete matched results before pagination, and edit tags in dialogs on the Tags page and reader toolbar. Keep node/parent context available on mobile.
- **Compact tree, timelines and batch organization** ([0a5bfad](https://github.com/turkerozturk/SweetCherry/commit/0a5bfad)): configurable tree font/padding, sortable parent columns in timelines/advanced search, reviewed batch moves and additive single-tag updates. Up to 200 explicit selections can be processed atomically; parent/child move selections are not moved twice.
- **Optional reversible Trash Bin** ([77d292f](https://github.com/turkerozturk/SweetCherry/commit/77d292f)): preserve IDs, subtrees, content, attachments, bookmarks and shared relationships. Store original placement and operation metadata; support reviewed restore and separately confirmed permanent deletion with stale-state/content checks.
- **Multiple-image insertion** ([45e471c](https://github.com/turkerozturk/SweetCherry/commit/45e471c)): select several PNG/JPEG files together and insert them vertically at the caret as one undoable rich-text edit, subject to the existing upload/object limits.
- **Optional CTBLOGS history** ([73fe79e](https://github.com/turkerozturk/SweetCherry/commit/73fe79e)): record maintained content/property/tag/move/bookmark operations in daily rotating ledgers, with before/after text/source, changed metadata and object manifests. Large sources use lossless ordered chunks. History writing and the covered edit share a transaction. Inspect/filter events and download full recorded text/source/JSON.
- **Image gallery** ([d503937](https://github.com/turkerozturk/SweetCherry/commit/d503937)): bounded lazy thumbnails, a larger viewer, metadata, search/sorting and original downloads. This release preparation also adds **one exact node-tag filter**, combined with text search and preserved across pagination. Case, Unicode and punctuation remain significant; `work` does not match `workshop` or `Work`.
- **Table gallery** ([c723338](https://github.com/turkerozturk/SweetCherry/commit/c723338)): previews and a larger scrollable viewer, header-first presentation, fixed-width cells, permanent 1 px solid borders and original XML downloads. Bounded visual settings are available in YAML and System settings.
- **Codebox gallery and attachments** ([988ebd7](https://github.com/turkerozturk/SweetCherry/commit/988ebd7)): syntax-filtered code previews/viewer, local highlighting, wrapping, copying and original source downloads. Attachment lists now use metadata-only queries, filename filtering, numeric byte-size/name sorting and 50-row pagination, with desktop/mobile layouts and protected single-file downloads.

## Upgrade and configuration

1. Stop SweetCherry and other applications writing to the same CTB. Keep separate verified backups of CTBs, configuration, tenant definitions, credentials, saved filters, exports and backup directories, including external/remote data sources.
2. Extract/install into a **new writable folder**, keeping the application folder intact. Transfer your own data/configuration deliberately; do not overwrite private data with demo files or copy old program/runtime files over the new version.
3. Existing external YAML takes precedence over packaged defaults. The optional Trash Bin and audit recorder both default to **false**; enable only if desired in **System → Settings**, then restart. Display/filter preferences stored in the browser retain their existing precedence.
4. Test on a disposable CTB copy, including your usual editing, shared-node, backup, synchronization, gallery and import/export workflows. Do not write to one CTB simultaneously from SweetCherry and CherryTree.

Merge into the existing `myapp` mapping rather than adding a duplicate mapping:

```yaml
myapp:
  trash:
    enabled: false
  audit:
    enabled: false
    max-event-characters: 16777216
  tree:
    font-size: 16
    vertical-padding: 1
```

No new schema migration is introduced. CTBLOGS and Trash Bin use ordinary managed nodes inside the CTB. Do not edit, import/merge, or manually rearrange their helper subtrees; whole-database copies/backups preserve their identities. Disabling the features does not remove existing history/trash content. Their automatic retention/purge is not implemented.

## Important behavior and limits

- **Trash is optional.** When it is disabled, the existing permanent-delete behavior remains. Restoring a subtree may require explicitly choosing root when its original parent no longer exists. Permanent purge is separate and irreversible.
- **CTBLOGS is selected-operation history, not a universal audit or backup.** Creation, duplication, imports, calendar date writes, trash/restore/purge, external CherryTree edits and direct SQL are not recorded yet. Binary images/attachments are not copied into history: manifests retain names, sizes and SHA-256 fingerprints. Table/codebox text is retained for covered content/property snapshots. No automatic content restore is provided. Failed audit writes or exceeded limits roll back the covered edit.
- **Old text remains readable.** Log nodes retain text subsequently removed from notes. The history UI is ADMIN-only, but anyone able to read the CTB through normal tree views or another program can inspect its ordinary log notes. History grows the database and is not tamper-proof.
- **Gallery views are read-only and bounded.** Shared occurrences do not duplicate stored object rows; objects retained in trash are included. IDs are `node_id:offset` and offsets can change after content edits. Stale data/download requests cannot silently read a newly selected database.
- **Image limits:** 320 px thumbnails, previews up to 2560 px, 64 MiB per payload and at most 100 million source pixels for decoding. Unsupported/damaged images show a message. GIF previews use the first frame; WebP previews depend on an available ImageIO decoder. Stored links are displayed, not fetched.
- **Table/codebox limits:** source reading/download is capped at 2,097,152 UTF-16 units per object. Tables display at most 100 columns and 10,000 cells including the header, with configured row limits. Long cells/code previews and viewers can be clipped with an explicit notice. Supported-size original downloads remain complete. Source code and table cell values are text, not executable/rendered HTML.
- **Attachment listing does not load every BLOB.** A new download reads one attachment inside its routed read transaction; drivers may buffer that individual file. Named raster-image attachments remain attachments. Embedded pictures, anchors and special LaTeX records are excluded from this list.

See [audit history](../en/audit-history.md), [image gallery](../en/image-gallery.md), [table gallery](../en/table-gallery.md), [codeboxes and attachments](../en/codebox-gallery-and-attachments.md), and the [release checklist](../tr/release-checklist.md) for complete behavior and settings.

## Build and validation

Build with JDK 17+ and the Maven wrapper; use Node.js 24 for `node --test src/test/js/*.test.cjs` (no npm install). Before this release preparation, the maintainer reported **907 Java tests, zero failures/errors and two skipped tests**, plus successful manual feature checks. The preparation build on Linux passed **906 Java tests and 195 JavaScript tests**, with no failures/errors, and verified the unchanged **203 packaged dependency-JAR hashes**. Exact platform test/skip counts can differ. The tagged Windows distribution workflow and final-package smoke checks are still required before publication.

Local tests do not certify the final Windows setup EXE. Verify the prepared commit's CI, build from `v1.10.0`, compare build metadata/checksums and smoke-test both final packages. No new dependency is introduced; the existing packaged-JAR notice inventory remains applicable.
