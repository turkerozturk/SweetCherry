# SweetCherry 1.7.0

Draft prepared on **4 November 2026**. Publication is deferred until the maintainer completes any further changes and checks. SweetCherry is an open-source web companion for CherryTree CTB note databases.

## Downloads and platforms

| Asset | Purpose |
| --- | --- |
| `sweetcherry_1.7.0_all_os_portable.zip` | Complete portable application and Windows/Linux/macOS scripts, **without Java**. Requires system Java 17+ matching the OS/CPU. |
| `sweetcherry_1.7.0_all_os_portable_with_java_and_setup.exe` | **Windows 10/11 x64** extraction/setup wizard, portable application folder, Windows Java 17 and optional shortcuts. |
| `sweetcherry-1.7.0-third_party_licences.zip` | Third-party licences and attributions, also included in both application packages. Optional separate download. |
| `sha256sums.txt` | SHA-256 checksums for those three product files. |

The Java-free ZIP is intended for Windows and Linux, including Raspberry Pi ARM, and includes macOS scripts. **macOS and 32-bit/i386 operating systems have not been tested.** A compatible Java installation and native libraries (including SQLite/JDBC) are required; a platform-neutral JAR does not establish compatibility with every OS/CPU combination. The EXE installer and bundled Java are **Windows x64 only**, despite the `all_os` filename. On another system, use the ZIP and that system's Java.

Extract the entire ZIP. Use `run.bat` on Windows, `sh ./launcher.sh` (desktop) or `sh ./run.sh` (terminal) on Linux/Raspberry Pi, or `sh ./run.command` on macOS. The retained `SweetCherry.exe` needs the runtime supplied by the Windows setup package; ZIP users on Windows should use `run.bat`. Calling Unix scripts with `sh` avoids reliance on ZIP executable-bit preservation.

`build-info.json` is inside both packages rather than a separate release asset. It records the application version, exact commit and Windows packaging tools/runtime provenance. `packageRuntimeIncluded` is false in the Java-free ZIP and true in the setup's application folder. The Windows runtime's own legal files remain in the setup package. All uploaded asset filenames are lowercase; GitHub supplies its own Source code links separately.

## New since 1.6.0

- **Folder-tree text ZIP export** (`80a455e`): download a selected node/subtree as nested folders and UTF-8 text. Preserve leaf extensions and code/Markdown source; use `_content.txt` for a parent node's own text. Rich text is flattened and binary objects become descriptions. Export choices are consolidated into one menu. [Guide](../en/text-tree-export.md).
- **Batch tag management** (`f11927a`): ADMIN users on writable connections can preview and confirm exact, case-sensitive tag renaming/removal. Merging de-duplicates tokens; failed operations roll back. Successful changes update Modified dates and produce per-node audit entries. [Guide](../en/tag-management.md).
- **Custom-list setup and editor comfort** (`a46494c`): configurable global/per-connection template names, setup status and confirmed creation of missing definitions, bilingual help, TAB/list-marker controls and boundary whitespace cleanup for authored node names. [Setup](../en/custom-lists-setup.md).
- **Consistent template reports** (`1b49204`): ordered fields across HTML list/table, PDF and XLSX, separate missing/empty/ambiguous diagnostics and repeated-definition notices. HTML adds search, incomplete-only filtering and a Today shortcut; PDF retains write-in space with corrected images/line breaks. [Guide](../en/template-reports.md).
- **Custom single-record HTML layouts** (`bd5c6cd`): multiple Plain Text designs under `_views`, record/field/time placeholders, configurable server time formatting and confirmed example creation. HTML is sanitized and isolated. Existing output types and the CTB schema remain available. [Guide](../en/record-layouts.md).
- **PDF from custom layouts** (`981839e`): A4 portrait download with embedded fonts/images, tables, external links and page totals. `{{now}}` is calculated at download; reading/exporting does not change source content or dates. The PDF engine supports a bounded subset of browser CSS. [Limits](../en/record-layouts.md#pdf-download).
- **Simpler release assets**: Java-free ZIP, clearly named Windows setup and licences archive, lowercase names/checksums and build metadata inside the packages.

## Upgrade and source builds

Stop SweetCherry and preserve your CTBs, external YAML, tenant definitions, credentials, exports, private saved filters and complete backup directories (catalogs and working copies included). Use a separate writable folder for the new version and deliberately transfer your data/settings; avoid copying demo data over private data or mixing runtime versions. Existing external YAML takes precedence. This release needs no CTB schema change. Read operations/exports leave notes unchanged; confirmed setup creation, tag operations and editing are writes.

GitHub's automatic Source code ZIP/tar.gz archives are source, not ready-to-run packages. Build the final tag with **JDK 17+** using the Maven wrapper/first-run scripts, then use the **entire generated `release/SweetCherry` folder**, not the JAR alone. Preserve its data, configuration definitions, run scripts, documentation and licence files. Building first requires internet access; running the prepared application does not require Maven.

## Validation and remaining limits

The maintainer previously reported **705 passing Java tests**, manually inspected the custom-layout PDF and pushed feature commit `981839e`. This records that feature validation, not a claim that the final 1.7.0 Windows packaging workflow has run. Build and check the final tagged commit before publication. The workflow verifies the ZIP excludes Java, compares its files with the setup staging tree, and exercises the installed Windows launcher without system Java.

Custom reports retain exact whole-tags-value membership and immediate-child field matching. HTML screen filters do not limit PDF/XLSX downloads. Custom layout PDFs support basic block/table CSS rather than a full browser layout engine; internal node links are inactive in standalone PDFs, and external resources are not fetched. Text ZIP export is not a full CTB backup and does not preserve binary attachments. Existing database, editor, synchronization and concurrent-write limits continue to apply. Keep backups on another device and avoid simultaneous writes from CherryTree and SweetCherry.

SweetCherry is GPL-3.0-or-later. `LICENSE`, `THIRD-PARTY-NOTICES.md` and `licenses/` remain in the application packages; the separate licences ZIP provides convenient access rather than replacing those copies.
