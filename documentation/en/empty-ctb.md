# Create an empty CTB database

Sign in as an administrator and open `/tenants/wizard`. Select SQLite and **Create a new, empty SQLite CTB in CTBDATA**. Enter a portable filename; `.ctb` is appended when omitted. The database is created in `CTBDATA` under the application working folder with the current CTB schema and no nodes. Selecting this option enables writable access in the form; review that setting before saving. Without JavaScript, select writable access yourself. Saving also creates the tenant configuration and uses the existing database-selection flow.

Existing CTBs, directories, symbolic links and SQLite sidecars (`-wal`, `-shm`, `-journal`) block creation. Case-only and Unicode-normalization variants are treated as collisions for portability. Registered data sources and `.txt` files in `allTenants` are checked for references to the same path, including missing databases. Use the existing connection when appropriate. Creation is available only for new SQLite connections; editing a connection or connecting to an existing CTB retains the existing behavior.

The existing portable filename rules reject paths, reserved Windows device names, invalid characters and overly long names. Leading/trailing spaces and dots are rejected. Spaces and Turkish letters can be used. The file is created exclusively, never by overwriting a file. Schema initialization or tenant-save failures remove only the newly created database. Filename/configuration conflicts have localized messages; check permissions, paths and free disk space for I/O failures. `CTBDATA` itself must not be a symbolic link.
