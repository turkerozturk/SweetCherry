# Draw over images

In **Image gallery**, ADMIN users on a writable connection can choose **Annotate image** on an embedded PNG, JPEG or BMP image or attachment. The server additionally checks that the owning node is real, unlocked and not a managed helper node. Other inline image formats can still appear in the gallery; the editor rejects unsupported formats before enabling drawing.

The editor uses the browser's local Canvas drawing support, without a CDN or additional drawing-library dependency. It supports arrows, rectangles, ellipses, lines and freehand strokes, color/width selection, undo/redo and reset. Coordinates and export use the original pixel dimensions even when the display is scaled down. With the canvas focused, Ctrl/Cmd+Z and Ctrl/Cmd+Y (or Shift+Z) operate the drawing history.

**Download original** saves a copy before editing. **Preview before saving** displays the merged PNG. Only **Confirm and overwrite image** sends the replacement; continuing editing, cancelling, drawing or undoing never writes to CTB. The resulting PNG replaces `image.png` at the same `(node_id, offset)`. PNG/inline filenames, anchor, justification, link and image time stay unchanged; named JPEG/BMP attachments receive a `.png` extension, while the owning node's `ts_lastsave` is updated. Shared occurrences display the same updated source image after reloading.

Saving flattens strokes into pixels. Drawing layers and in-editor undo history do not survive saving/reopening. There is no automatic original-image archive; retain the downloaded original or a CTB backup if you need recovery. CTBLOGS, when enabled, records this as a content edit with object fingerprints; it does not archive old binary images. After a successful save use **Reload editor** for more drawing, or open the gallery/node again.

Replacement requires ADMIN, CSRF, the current tenant token, a writable connection, an unlocked owning node, explicit confirmation, and an unchanged revision. The revision covers the source image, relevant image metadata and owning content state. Updates recheck the source under a database lock/compare-and-swap and run atomically with the node timestamp. A stale editor, moved/deleted object or changed image is rejected rather than overwritten. The unsaved drawing remains visible after an error.

Static PNG, JPEG and BMP sources are accepted, up to 16 MiB, 8192 pixels per edge and 12 million pixels in total. Animated PNGs, GIF/WebP/TIFF/SVG and other image formats, anchors, LaTeX/non-image attachments, changed dimensions and protected helpers are rejected. Uploaded PNGs are decoded and re-encoded on the server; concurrent opening/saving is bounded. The first version does not provide text labels, object selection/repositioning, cropping or resizing. Reset removes only the current unsaved strokes, not pixels that were already part of the opened image.

JPEG/BMP sources are converted to PNG when opened; saves always write PNG. This avoids another lossy JPEG encoding step and preserves the decoded pixels, but may increase file size. JPEG EXIF orientation (including mirroring) is applied before editing; other source metadata is not retained by conversion. Output is still stored in the existing `image.png` BLOB column. No schema changes are needed.
